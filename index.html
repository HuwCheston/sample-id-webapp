Reproducing

First things first, clone the repository to a new directory, and install the requirements:

git clone sample-id
cd sample-id
pip install -r requirements.txt    # using a venv is *strongly* recommended

You'll also want to install ffmpeg (for preprocessing audio, and probably required for dependencies) and gsutil ( recommended if hosting source material on a GCS bucket, rather than locally).

Acquiring the Audio Tracks

  1. Acquire the required audio files from the databases listed below.

    • Free Music Archive
    • MTG-Jamendo
    • MusDB18
    • Magnatagatune

    To see which files are needed, refer to references/dataset.json. The top level entries here are database names: each contains an iterable of tracks, where each item (unsurprisingly) relates to a single track from the database. Refer to the top level comments field for information on how the source_id for each track relates to an entry in the respective database.

  2. As the format of filenames for each database is different, we use a unified filestructure consisting of the database name (or an abbreviation), followed by a zero-padded number. Each track should be renamed with the filename given in the fname field of dataset.json. So, for the track "8/beth_quist-lucidity-11-the_house_that_jack_built-465-494.mp3" in the magnatagatune database, we'd rename it to magnatagatune.00000.wav.

  3. Ensure the file structure looks like this:

    └── root/
    ├── data/
    │   ├── fma/
    │   │   └── mix/
    │   │       ├── fma.00000.wav
    │   │       └── fma.00001.wav
    │   ├── mtg-jamendo/
    │   │   └── mix/
    │   │       └── mtg-jamendo.00000.wav
    │   ├── musdb18/
    │   │   └── ...
    │   └── magnatagatune/
    │       └── ...
    ├── references/
    │   └── dataset.json
    └── README.md <- you are here

Preprocess the Audio

  1. We extracted short 30-second excerpts from each track, the start and stop point for which can be found in the clip_start and clip_end fields for each track in database.json. You can use any method to do this, but we used ffmpeg:

    ffmpeg -ss HH:MM:SS -to HH:MM:SS -i PATH_TO_INPUT.wav -c copy PATH_TO_OUTPUT.wav

  2. For source separation, we used the default model in demucs v.4.0.1. For each track, the command was simply:

    python3 demucs PATH_TO_INPUT.wav

  3. We combined the separated bass and other sources from demucs, again using ffmpeg:

    ffmpeg -i PATH_TO_BASS_SOURCE.wav -i PATH_TO_OTHER_SOURCE.wav -filter_complex amix=inputs=2:duration=longest PATH_TO_OUTPUT.wav

  4. Finally, we summed each source to mono and downsampled to 22050 Hz/16-bit:

    ffmpeg -i PATH_TO_ONE_SOURCE.wav -ar 22050 -ac 1 -acodec pcm_s16le PATH_TO_OUTPUT_SOURCE.wav

  5. You now need to adjust the output filestructure to include these seperated tracks:

    └── root/
    ├── data/
    │   ├── fma/
    │   │   ├── bass+other/
    │   │   │   ├── fma.00000.wav
    │   │   │   └── fma.00001.wav
    │   │   ├── drums/
    │   │   │   ├── fma.00000.wav
    │   │   │   └── fma.00001.wav
    │   │   └── vocals/
    │   │       ├── fma.00000.wav
    │   │       └── fma.00001.wav
    │   ├── mtg-jamendo/
    │   │   ├── bass+other/
    │   │   │   └── ...
    │   │   ├── drums/
    │   │   │   └── ...
    │   │   └── vocals/
    │   │       └── ...
    │   ├── musdb18/
    │   │   └── ...
    │   └── magnatagatune/
    │       └── ...
    ├── references/
    │   └── dataset.json

Acquire and Preprocess Validation Audio

  1. Our validation dataset consists of 76 queries, 68 candidates and 320 “noise” tracks of a similar genre. All tracks are commercial recordings by well-known artists and thus cannot be released publicly. Track titles and artists are given in inference/jvb_uris.csv.

  2. After acquiring this audio, it must also be resampled to 22050 Hz/16-bit mono, with ffmpeg (reuse the command above).

  3. These audio files must be placed inside a folder from the root directory: inference/audio/*.wav. The filenames for each audio file should follow the index in inference/jvb_uris.csv. Queries and candidates should be prefaced with T and noise with X:

    └── root/
    ├── inference/
    │   ├── audio/
    │   │   ├── T001.wav    # Query: ("Time's Up", OC)
    │   │   ├── T002.wav   # Candidate: ("A Day in the Life", Les Demerle)
    │   │   ├── ...
    │   │   ├── X001.wav    # Noise: ("Another Day", Jamie Lidell)
    │   │   └── X002.wav   # Noise: ("The Mexican", Babe Ruth)
    │   └── jvb_uris.csv
    └── README.md <- You are here

Training

  1. First, generate all the starting + stopping timestamps and sample instruments for the audio tracks in the database by running:

    python sample_id/get_data/create_dataset_csv.py

    This will dump train_split.csv and test_split.csv files inside the references folder.

  2. Next, we want to test that we can generate examples from the artificial dataset. To do so, run:

    python sample_id/dataloader.py

    This will create 1000 random training and test examples and dump them as individual folders to references/triplet_metadata. Each folder will contain the anchor and positive audio as .wav files, as well as a .json file detailing the source material and any manipulation(s) applied. The script will also list any missing audio files that could not be found locally.

  3. Now, we can start training by running:

    python sample_id/training_local.py --config "path/to/config.json"

    The --config flag should point towards a .json file in the config directory that contains information on how the experiment should be run. Here is an annotated example:

    {
  "run_name": "debug-local",    # The name of the experiment
  "encoder": "bytecover",    # The encoder: either vision-transformer or bytecover
  "share_encoder_weights": false,    # Whether or not to use a single encoder (default = False)
  "inference_uses_same_encoder": true,    # Whether or not to only use a single encoder at inference (default = True)
  "loss_func": "triplet&cross-entropy",    # The loss function: either triplet, cross-entropy, or triplet&cross-entropy (default)
  "cce_constant": 0.3,    # The value to multiply the cross entropy loss by
  "triplet_constant": 0.7,    # The value to multiply the triplet loss by
  "split_batch_into": 1,    # Split a single batch into this many mini-batches
  "batch_size": 128,
  "num_epochs": 100,
  "learning_rate": 1e-4,
  "learning_rate_plateau_epochs": 40,    # After this many epochs, reduce learning rate by learning_rate_decay
  "learning_rate_decay": 0.2,
  "train_size": 128,
  "test_size": 128,
  "margin": 0.3,    # The margin to use in setting the triplet loss
  "num_workers": 0,    # Number of workers to use in multiprocessing: set to 0 to disable multiprocessing
  "debug": false    # Setting to True will use silent audio of 5 seconds duration, rather than audio from the artificial dataset
}

    As training continues, loss and mRR will be logged for both the training and test datasets in the console, as well as validation metrics. A range of plots will be saved to reports/{run_name}/{epoch_number} after each epoch, as well a checkpoint to checkpoints/{run_name}/{checkpoint_number}

  4. To resume training from a given checkpoint, set checkpoint_path inside config.json to the location of the .pt file. Training will automatically resume from the next epoch after the checkpoint was made.
